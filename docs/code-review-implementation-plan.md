# FMS 代码审查整改与功能扩展计划

> 计划日期：2026-08-04
>
> 依据：[`code-review.md`](./code-review.md)
>
> 目标：逐项完成生产安全、插件容错、平台化与 FMS 业务功能扩展，并保持代码、测试和文档状态同步。

## 1. 状态说明

| 标记  | 含义                               |
| ----- | ---------------------------------- |
| `[ ]` | 待开始                             |
| `[~]` | 实施中，验收证据尚不完整           |
| `[x]` | 代码、测试、文档和指定验证均已完成 |
| `[!]` | 存在需要外部决策或系统支持的阻塞   |

完成标准不以“已写代码”为准，每项必须同时满足：

1. 行为已实现，且不依赖未记录的手工步骤。
2. 聚焦回归测试覆盖成功、失败和边界路径。
3. `pnpm typecheck`、`pnpm lint`、`pnpm test` 和 `pnpm build` 在相关范围内通过。
4. 产品或界面变更通过真实浏览器验证。
5. 本文的状态、验证证据和实际代码一致。

## 3. Phase 0：生产安全隔离

### FMS-001 生产构建禁用 Mock

- 状态：`[x]`
- 对应审查项：3.1 原 P0，当前已修复。
- 代码范围：`apps/web/src/main.tsx`、Vite 环境配置、`apps/web/package.json`。
- 实施：只有开发模式且显式设置 `VITE_ENABLE_MOCKS=true` 时才动态导入 MSW。
- 验收：标准生产构建不生成 MSW chunk，也不包含 `mock-admin-token` 和 `admin123`。
- 测试：产物内容检查脚本；开发 Mock 启动烟雾测试。

### FMS-002 演示登录与生产登录分离

- 状态：`[x]`
- 对应审查项：3.1 原 P0，当前已修复。
- 代码范围：`LoginPage.tsx`、环境类型、登录流程测试。
- 实施：演示账号切换器和预填密码仅在 Mock 开发模式出现；其他环境使用空表单。
- 验收：生产 DOM 不包含“演示账号”、`admin123` 或 `viewer123`。

### FMS-003 应用启动失败恢复

- 状态：`[x]`
- 对应审查项：3.1 原 P0，当前已修复。
- 实施：拆分 `bootstrapApplication`；Mock 启动错误不形成无信息空白页，开发环境展示诊断状态。
- 验收：模拟 `worker.start` 失败时，用户可见错误且可重试。

## 4. Phase 1：插件发现与校验

### FMS-101 对 `unknown` 插件执行安全 Schema 校验

- 状态：`[x]`
- 对应审查项：3.2、3.9。
- 实施：`validatePlugins` 先执行无抛错结构解析，再执行语义与全局校验。
- 验收：`null`、缺少 manifest、字段类型错误、非函数 loader 均返回可读错误，不抛出异常。

### FMS-102 发现描述符与加载故障隔离

- 状态：`[x]`
- 对应审查项：3.2。
- 实施：虚拟模块导出 package descriptor 与动态 loader，宿主使用 `Promise.allSettled` 加载。
- 验收：单个插件缺少 export 或顶层抛错时，其他插件和宿主仍可用。

### FMS-103 统一发现与注册诊断

- 状态：`[x]`
- 实施：注册结果包含 packageName、packageVersion、manifestVersion、阶段和错误码。
- 验收：插件中心可区分 discovery、load、schema、compatibility 和 contribution 错误。

### FMS-104 依赖图、循环与级联错误校验

- 状态：`[x]`
- 对应审查项：3.9。
- 实施：扩展 manifest required/optional dependencies，校验目标注册状态和扩展循环。
- 验收：必选依赖不可用时源插件不会被标记为 ready；循环具有完整错误路径。

## 5. Phase 2：运行时状态与可恢复性

### FMS-201 插件状态判别联合与重试

- 状态：`[x]`
- 对应审查项：3.3。
- 实施：注册状态区分 loading/ready/error，保留最后成功快照，暴露 `reloadStates`。
- 验收：`/api/plugins` 失败时菜单不被伪造成全部停用，Layout 和插件中心显示可重试错误。

### FMS-202 插件 chunk 加载真实重试

- 状态：`[x]`
- 对应审查项：3.4。
- 实施：重试时重建 lazy 实例，并支持一次发版 chunk 失效刷新策略。
- 验收：首次 loader reject、第二次 resolve 时页面成功恢复。

### FMS-203 异步 channel 异常隔离

- 状态：`[x]`
- 对应审查项：3.5。
- 实施：监听器支持 Promise，所有 rejection 通过统一报告函数捕获。
- 验收：失败异步订阅者不会产生 `unhandledrejection`，健康订阅者仍收到消息。

### FMS-204 统一 Route Catalog 与可访问默认页

- 状态：`[x]`
- 对应审查项：3.7。
- 实施：宿主路由单一配置源，菜单按权限过滤，登录后进入首个可访问页。
- 验收：只拥有 `reports:view` 的用户不会默认落到 Dashboard 403；回跳保留 query/hash。

### FMS-205 可访问性与导航基线

- 状态：`[x]`
- 对应审查项：3.13、3.14。
- 实施：跳过导航链接、页面 `h1`、稳定异步容器、可见焦点，消除嵌套交互元素。
- 验收：核心流程通过键盘导航与 axe 自动检查。

## 6. Phase 3：数据层与 FMS 业务页

### FMS-301 共享 Query Service 和 DTO Schema

- 状态：`[x]`
- 对应审查项：3.6、4.1。
- 实施：宿主 runtime 提供查询去重、缓存、取消、超时、重试和 Schema 解析。
- 验收：相同 query key 只发起一次并发请求；页面卸载后不更新状态且可取消请求。

### FMS-302 工作台实时控制塔

- 状态：`[x]`
- 实施：渲染在途、待调度、异常、完成、准时率等 KPI，保留类型化插槽。
- 验收：工作台无串行重复请求，具有 loading/error/empty/ready 状态和最后更新时间。

### FMS-303 履约报表数据表格

- 状态：`[x]`
- 实施：展示运单列表，支持承运商/状态筛选、列排序、空状态和可保存 URL 查询。
- 验收：channel 传入承运商后立即更新表格，路由入口与报表操作均可用。

### FMS-304 承运商评级与风险视图

- 状态：`[x]`
- 实施：展示等级、评分、准时率、事故、趋势和风险状态，摘要模块向报表发送筛选。
- 验收：评级页与 two 插槽使用同一类型化 DTO，低分承运商具有明确风险标识。

## 7. Phase 4：插件平台能力

### FMS-401 插件中心 2.0

- 状态：`[ ]`
- 对应审查项：5.1、6。
- 实施：密集表格展示包名、ID、版本、协议、状态、贡献、错误和启停操作。
- 验收：支持状态筛选、错误详情、依赖影响提示和单项并发 pending 状态。

### FMS-402 插件配置、生命周期与租户范围

- 状态：`[ ]`
- 实施：增加 JSON Schema 配置、activate/deactivate/dispose 钩子和 tenant/role 启用范围。
- 验收：配置更改可校验、审计和回滚；停用后相关订阅与资源已清理。

### FMS-403 宿主能力注册表

- 状态：`[ ]`
- 对应审查项：4.2。
- 实施：为 runtime 增加 logger、notifications、commands、storage 和 telemetry。
- 验收：插件不直接调用宿主内部实现，能力均具有插件命名空间。

### FMS-404 契约所有权与 CSS 作用域

- 状态：`[~]`
- 对应审查项：3.8、3.10。
- 实施：拆分 host/two/three contract 所有权；每个可发布插件输出作用域 CSS。
- 验收：外部插件不依赖其他插件实现包；停用插件不能通过样式影响宿主。
- 当前进度：three 已使用 Tailwind `prefix(three)` 隔离工具类并增加生产产物检查；契约拆分、内部插件独立 CSS 和停用样式生命周期尚未完成。

## 10. 每轮交付清单

每完成一批任务，必须同步执行：

1. 更新本文对应任务状态和执行日志。
2. 更新 `code-review.md` 中已不符合当前代码的陈述。
3. 运行聚焦测试后，运行全仓 typecheck、lint、test 和 build。
4. 对 UI 变更运行桌面端与移动端浏览器验证。
5. 记录未完成项的下一个具体动作，不使用模糊的“后续优化”。
